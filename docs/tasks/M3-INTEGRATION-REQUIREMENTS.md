# M3 任务卡：资方接入助手最小闭环

- 状态：历史能力，核心闭环已实现；当前暂缓扩展，发布事件记录待补，DTO 生成骨架为可选未实现
- 当前执行依据：否；本期主线以资方知识库和智能守护为准，见 ADR-011 与 ROADMAP
- 对应路线图：M3
- 依赖：M2 RAG 证据链已验收
- 首个业务范围：用信申请接口
- 补充依赖：接口通用协议证据（HTTP 方法等）必须已进入可追溯 RAG 索引；未覆盖时只能拒绝发布。

## 目标

把 M2 返回的可追溯文档证据，转换为一份“用信申请”候选接口规范。候选规范必须经过 Java 确定性校验和人工确认，才能发布为不可变的 V1；模型不能直接发布，也不能覆盖已发布版本。

## 输入与输出

### 输入

- 文档标识、文档版本和 M2 返回的证据引用；
- 接口用途、请求地址、请求方法、字段表、错误码和幂等约定等证据；
- 仅允许使用 `ACCEPTED` 的 RAG 证据，证据不足时停止抽取。

### 候选输出

- 资方标识、接口标识、接口用途；
- 请求地址和 HTTP 方法；
- 字段：名称、类型、必填级别、条件、说明和来源引用；
- 错误码、幂等约定及来源引用；
- `candidateId`、来源文档版本、抽取模型和创建时间；
- 状态：`DRAFT`、`REJECTED`、`PENDING_REVIEW`、`APPROVED`。

### 发布输出

- `PublishedContractVersion` 不可变版本；
- 版本号、生效时间、确认人、确认时间和候选来源；
- 只读查询结果和发布事件记录。

## 确定性校验

1. **结构校验**：必填标识、接口方法、字段名称、字段类型和来源引用不能缺失。
2. **业务校验**：金额字段必须为非负数类型；必填级别只能是 `REQUIRED`、`CONDITIONAL`、`OPTIONAL`；条件必填必须同时有触发条件和来源。
3. **来源校验**：每个接口事实和字段事实必须能定位到 M2 的 `chunkId`、文档版本、章节或表格行；引用不存在或跨版本时拒绝。
4. **版本校验**：已发布版本只读，修正必须创建新的候选和新的发布版本；候选状态不能被诊断链路读取。

## 人工确认

- `PENDING_REVIEW` 只能由项目所有者确认、拒绝或退回修改；
- 结构校验、业务校验或来源校验失败时不能进入确认通过；
- 确认通过后生成不可变 V1；确认拒绝保留原因和候选快照；
- 本阶段不执行真实资方调用，不生成生产写操作。

## Java 实现边界

- 模型只负责从已接受证据中提出候选事实；Java 负责 DTO 映射、枚举、来源、版本和状态校验；
- 使用现有 `fund-integration` 模块，保持领域对象与应用编排分离；
- 不引入数据库迁移，先用可复现的合成候选和内存端口验证流程；持久化适配器另列任务；
- 所有 Java 类和方法提供简短中文注释。

## 验收

1. 有效候选能通过结构、业务和来源三层校验。
2. 缺字段、错误类型、非法必填级别、缺条件、伪造引用和跨版本引用均被拒绝。
3. 候选未经人工确认不能发布，发布后不能原地修改。
4. 拒绝和退回均保留原因，可按 `candidateId` 模拟。
5. 已发布版本可被只读查询，候选版本不可被查询。
6. Maven 测试覆盖上述通过、拒绝、重复确认和版本不可变场景。

## 不在 M3 范围

- 多资方、多接口批量抽取；
- DOC、XLS、PDF 新格式解析；
- 真实资方网络调用、签名和生产数据库迁移；
- 自动生成完整 SDK 或生产代码；
- 智能守护实时指标、MQ 和 Agent 联合诊断。
