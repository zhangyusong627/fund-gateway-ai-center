# M2 任务卡：知识底座与 RAG 闭环

- 状态：已完成（2026-09-10 阶段验收）
- 对应路线图：M2
- 首个输入：升恒消费金融接口文档 DOCX
- 首个业务范围：4.2 授信申请
- 本阶段目标：把 D4 的向量检索实验升级为可追溯、可评测的文档 RAG

## 业务目标

让使用者针对“授信申请”提问时，系统能够从指定文档版本中找到正确正文或表格行，返回答案所需的原文证据和来源位置。M2 不抽取或发布接口规范；它只建立 M3 可依赖的知识证据。

## 输入与输出

### 输入

- 文档：`升恒消费金融接口文档.docx`
- 文档版本标识、文件哈希和登记时间
- 范围：4.2 授信申请及其请求/响应字段表
- 查询：围绕接口用途、前置条件、字段含义、必填/条件必填和错误结果的固定问题集

### 输出

- 文档版本记录
- 带顺序和来源位置的文本分块
- 使用 `BAAI/bge-small-zh-v1.5` 生成的 512 维向量
- pgvector 中可查询的索引
- Top-K 检索结果：分块内容、相似度、文档版本、章节、块编号和表格坐标
- 固定问题集的 Recall@K、引用命中率和失败案例

## 处理链路

```text
登记 DOCX
→ 校验哈希与版本
→ 解析段落和表格
→ 定位 4.2 授信申请
→ 按章节、段落和表格行切分
→ BGE Embedding
→ 写入 pgvector
→ 查询实时向量化
→ Top-K 检索
→ 返回引用
→ 固定集评测
```

## 结构与状态

- 文档状态：由 `DocumentIndexLifecycle` 约束 `REGISTERED → PARSED → INDEXED`；失败进入 `PARSE_FAILED` 或 `INDEX_FAILED`。
- 索引必须绑定文档版本、Embedding 模型、维度、归一化配置和切分版本。
- 同一文档版本与索引版本重复执行必须幂等。
- 旧版本不能静默覆盖新版本，查询必须明确选择生效版本。
- 解析失败的内容不能进入可检索集合。

## 分块规则第一版

- 标题与其后正文保持关联。
- 普通段落按语义边界组合，不能从句子中间硬切。
- 表格以“表头 + 单行数据”为最小证据块，防止字段名、类型、必填条件和说明分离。
- 每个块保留章节路径、段落序号；表格块额外保留表格序号和行号。
- 超长块再按字符上限拆分，并保留前后少量重叠；具体上限通过首轮分布统计确定，不预先虚填。

## 检索策略

- 基线：pgvector 余弦距离 Top-K。
- 改进：向量得分与字段名/关键词精确命中做简单融合。
- 本阶段不引入独立全文检索引擎、重排模型或知识图谱。
- 查询向量和文档向量必须使用同一 BGE 模型、512 维和同一归一化配置。

## 固定评测问题类型

至少覆盖以下类型，每题在运行模型前人工确认期望证据块：

1. 授信申请接口的业务用途。
2. 发起申请前需要完成什么前置操作。
3. `applyAmt` 的字段含义与示例。
4. 某个请求字段是否必填。
5. 一个条件必填字段的触发条件。
6. 处理失败时返回字段的要求。
7. 一个文档范围内不存在的问题，用于验证无证据停止。

第一版不少于 10 题，最终评测集在调参前锁定，避免按结果修改答案。

## Java 实现边界

- DOCX 使用成熟 Java 解析库处理正文和表格，不手写 ZIP/XML 解析器。
- 复用现有 `LocalBgeEmbeddingModel`，但将实验入口改造成可注入的知识能力。
- 复用 pgvector，不再使用 `SyntheticVectorRetriever` 作为正式检索实现。
- 领域对象、端口和服务提供简短中文注释。
- 使用 Java 8 之后新增语法或 API 时，在代码讲解中标明引入版本和 Java 8 写法。
- 数据库 Schema 和表创建必须取得用户单独授权；授权前可完成 Java 接口、解析器、分块器和测试设计。

## 正常预期

- 文档解析能保留 4.2 节正文与字段表关系。
- 同一问题重复查询结果稳定。
- `applyAmt` 查询能召回包含字段名、必填信息和说明的同一证据块。
- 返回的引用可以定位到文档版本、章节及表格行。
- 改进策略相对基线的结果可量化比较，即使没有提升也必须保留真实结论。

## 失败预期

- 文件损坏或格式不支持：停止解析并记录原因。
- 文档未找到目标章节：不建立该范围索引。
- Embedding 失败：不写入半成品索引。
- 向量维度或模型版本不匹配：拒绝写入和查询。
- 无相关证据：返回“证据不足”，不让模型补猜。
- 数据库不可用：查询明确失败，不回退到伪造结果。

## 不在 M2 范围

- DeepSeek 生成最终业务答案（本阶段仅保留一次受证据门禁约束的联调验证，不作为业务发布能力）。
- Redpanda 指标链路和智能守护 Agent。
- DOC、XLS、PDF 全格式一次性支持。
- Redis、重排模型、知识图谱和生产监控接入。

## 验收方式

1. Maven 测试覆盖段落、表格、章节边界、状态流转、维度不匹配和无证据场景；幂等写入通过 pgvector 重复执行证据验证。
2. 使用目标 DOCX 完成一次真实解析，保存解析摘要与分块样例。
3. 经授权后建立 `knowledge` Schema 表并完成真实离线索引与在线检索。
4. 运行不少于 10 题的固定评测，输出 Recall@K、引用命中率和失败列表。
5. 保存模型无关的完整 RAG 轨迹：输入问题、查询向量元信息、Top-K、得分、引用和评测结论。
6. 完成核心代码时序讲解、Java AI 知识讲解和三层学习验收。
