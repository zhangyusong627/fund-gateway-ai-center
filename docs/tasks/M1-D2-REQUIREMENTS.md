# 历史任务卡：原 M1-D2 风险事件触发与多指标诊断评测

> 状态：已被 ADR-010 和新版 ROADMAP 替代，不再作为当前任务入口。实时指标链路调整为 M4；当前下一步是 M2 知识底座与 RAG。本文件保留用于追溯早期设计，不据此开工。

## 业务目标

验证智能守护 Agent 如何从高吞吐运行指标中提取风险特征，在正式故障前触发低频诊断，并让大模型完成多证据根因分析和治理建议生成。

## 输入

- 合成运行指标：QPS、CPM、平均延迟、P95、P99、超时率、错误率、HTTP/Tomcat 线程池、GC 次数和耗时。
- 已发布资方接口规范：接口 QPS 上限、超时上限及版本。
- 历史指标趋势和历史故障记录。
- 第一版窗口：10 秒和 1 分钟；1 秒与 5 分钟窗口只保留扩展能力，避免首版同时维护四种窗口。

## 处理链路

```text
Mock指标 → Redpanda → 窗口聚合 → 特征计算 → 单指标/组合规则 → 事件去重冷却 → 诊断快照 → Agent → 结构化门禁
```

- 指标事件只进入聚合和特征计算，不逐条调用模型。
- 单指标规则识别局部风险，多指标组合规则形成风险事件。
- 同一接口、同一风险指纹在冷却窗口内只生成一次诊断任务。
- Agent 只读取诊断快照和必要历史证据，不执行写操作。
- 根因排序差异只记录；模型否认确定性规则、引用无效事实或提出越权动作时转人工审核。

## 触发示例

| 条件 | 结果 |
|---|---|
| QPS 达到已发布接口规范上限 80% | WATCH |
| QPS 达到 90% | 容量诊断事件 |
| P99 连续三个窗口上升 | 延迟诊断事件 |
| 超时率升高 + 历史上游超时 | 上游复发诊断事件 |
| 线程池水位升高 + GC 耗时增加 | 资源耗尽诊断事件 |
| 关键证据缺失 | 标记证据不足，停止形成确定结论 |
| 模型与硬规则冲突 | 保存证据并进入人工审核 |

## 模型职责

- 关联多个指标和历史证据；
- 排序根因候选；
- 指出还需要补充的证据；
- 生成只读治理建议。

模型不负责计算 P95/P99、执行阈值判断、去重限流或修改配置。

## 验收标准

- 高吞吐输入可聚合为少量窗口特征，不逐条调用模型；
- 单指标和组合规则均有可重复结果；
- 冷却和去重能抑制重复诊断；
- 预防性场景可在正式告警前触发；
- 事后告警场景可生成诊断快照；
- 模型报告与规则一致、冲突、门禁失败三类结果均有证据；
- 全链路可统计触发次数、模型调用次数、耗时和 Token。
- Redpanda 真实生产和消费链路可运行；原始指标不永久全部写入 PostgreSQL。
- P95/P99 基于同一有界窗口样本计算，不对已有百分位再次求平均。
- 去重、冷却和频控第一版由 PostgreSQL 唯一约束、持久化时间字段和应用逻辑实现；本期不引入 Redis。

## 不在本次范围

- 不接入真实 Prometheus、SkyWalking 或生产监控平台；
- 不部署异常预测模型；
- 不执行配置修改、审批或自动恢复；
- 不引入 Kafka Streams、Flink、微服务或 Kubernetes。
