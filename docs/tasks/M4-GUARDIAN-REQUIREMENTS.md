# M4 任务卡：智能守护实时指标链路

- 状态：核心闭环已实现；历史任务卡，当前不再单独作为开工入口
- 验收证据：`docs/learning/M4-*`、`docs/learning/M5-*`、`docs/learning/M8-memory-agent-acceptance-20260914.md`
- 对应路线图：M4（9/20–9/23）
- 依赖：M1 规则基线、M2 RAG、M3 已发布契约查询能力

## 业务目标

让智能守护在收到高吞吐运行指标后，先由确定性特征与规则判断风险，再按风险指纹去重和冷却，生成少量可供后续 Agent 诊断的任务；正常指标不触发诊断。

## 输入 / 输出

- 输入：Mock 监控指标事件，包含接口、时间、请求数、错误数、延迟分位数、线程池和 GC 等字段。
- 输出：10 秒和 1 分钟窗口聚合特征、规则命中结果、风险指纹、诊断任务事件及可回放记录。

## 状态与异常分支

- 消息格式错误：记录拒绝原因，不进入聚合。
- 重复事件：按事件 ID 幂等处理。
- 单指标命中：生成低复杂度风险任务。
- 多指标组合命中：生成高置信度风险任务。
- 冷却窗口内重复风险：抑制新任务并记录抑制原因。
- MQ 或数据库不可用：保留明确失败状态，不调用大模型。

## 约束（不能做什么）

- 只使用合成指标和本地 Mock 生产者，不接入真实监控系统。
- 不在 M4 调用大模型；模型联合诊断属于 M5。
- 不引入 Redis；缓存需求须以后续实测和 ADR 为依据。
- 不执行真实治理写操作。

## 正常预期 / 失败预期

- 正常指标不会创建诊断任务。
- 风险场景可稳定复现并创建任务。
- 重复风险在冷却期内被抑制。
- 指标消息数量显著大于诊断任务数量。

## 验收方式

- 本地 Redpanda 可启动，Mock 生产者和消费者完成端到端回放。
- 覆盖两个单指标场景和一个多指标场景；验证 10 秒、1 分钟窗口、P95/P99、错误率、线程池、GC 等特征。
- 验证 PostgreSQL 幂等、风险指纹和冷却；统计消息数与诊断任务数并保存证据。
- `mvn -B verify`、运行日志和回放结果均通过后，更新 HANDOFF。
