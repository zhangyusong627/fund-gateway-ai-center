# FG-ADC 项目执行路线图

本文件是项目内的执行索引，不替代外部的完整学习规划。外部总规划负责完整课程、时间投入和里程碑验收；`docs/DAILY_PLAN.md` 负责每日安排；`docs/EXECUTION_PROTOCOL.md` 负责每日核对机制；`docs/HANDOFF.md` 负责当前状态、交接日志和下一步唯一动作；`docs/adr/` 负责已经冻结的技术决策。

## 当前状态

当前处于 **M0-D2 完成后的切换点**：D1、D2 的工程实现和阶段认证均已完成；下一步进入 D3。

## M0：机制与立项

目标是建立 Java AI 工程骨架，并验证模型调用、结构化输出、工具循环和最小检索的基本机制。

| 任务 | 内容 | 主要产物 | 状态 |
|---|---|---|---|
| D1 | 工程骨架、版本基线、首次 DeepSeek 调用 | 五模块工程、ADR-000、脱敏调用证据 | 已完成并通过阶段认证 |
| D2 | 结构化输出 | 合成样例：合法、缺字段、格式合法但业务非法 | 已完成并通过阶段认证 |
| D3 | 工具循环 | `ToolCallingAdvisor` 能力验证、步数预算、失败路径 | 当前任务 |
| D4 | 最小向量检索 | 合成中英混排、表格、流程图文本化样例与评测 | 待开始 |
| D5 | 最小契约与诊断案例 | 契约字段、诊断输入、首批验收集 | 待开始 |

## M1：最小诊断

建立合成知识、确定性规则基线、三个只读工具和可停止的 Agent 诊断流程；对比规则与 Agent 的输出，并保存证据。

## M2：可控执行

加入审批、模拟执行、状态持久化、预算和恢复；验证重复批准、审批过期、拒绝、超时和进程中断。

## M3：RAG 闭环

完成索引与版本、检索、引用和独立评测；比较至少两种检索策略，确认更新不会混用旧证据，并能定位检索失败原因。PostgreSQL + pgvector 在此阶段接入。

## M4：接入助手

实现人工确认后的资方契约、确定性骨架、受限方法体生成和隔离验证；即使代码编译通过，语义错误也必须能被拦截。

## M5：交付验收

完成独立演示、共享契约版本测试、Compose、流水线和完整讲述；在干净环境复现，并能解释未知故障的定位过程和系统限制。

## 使用顺序

1. 先读本文件，了解阶段和任务编号。
2. 再读 `docs/DAILY_PLAN.md`，确认当天安排。
3. 再读 `docs/HANDOFF.md`，确认当前唯一动作。
4. 涉及技术决策时读取 `docs/adr/` 下相关 ADR。
5. 每个任务先完成实现，再完成“已运行 / 已理解 / 已独立验证”三层验收。
