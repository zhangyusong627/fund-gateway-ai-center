# 范围与验收

## 做什么
FG-ADC 是使用合成场景的 Java + AI 学习型工程，采用一个仓库、五个模块、单 Spring Boot 进程。异常诊断助手与资方接入助手分别演示；连接点仅为人工确认后发布的不可变资方契约版本。治理动作全部模拟执行。

本次只做 M0 / D1：Initializr 工程骨架、BOM 核对、ADR-000 基线、工程规则、范围页、一次 DeepSeek 调用的脱敏报文、架构草图和复盘。代码命名与注释整理遵循 ADR-002。

## 不做什么
D1 不实现诊断规则、工具循环、审批执行、向量检索、生成代码、页面功能或数据库；后续分别按任务卡推进。当前项目使用用户提供的合成材料；不宣称生产系统或真实流量；不引入 Python、微服务、K8s、消息队列、Redis、多 Agent 平台，不公开部署。

## 验收是什么
- 五模块 `mvn -B verify` 通过；原始 Initializr 上下文测试保留；空壳在回环地址启动。
- Boot 4.1.1 / Spring AI 2.0.1 BOM 可解析，实际依赖无人工覆盖；JDK 21、Maven 3.9.16 有现场证据。
- DeepSeek `deepseek-v4-flash` 返回成功，留 HTTP 状态、脱敏请求、响应及 token 用量；认证与提示全文不落盘。若响应回显提示，则去除回显部分并明确标注，不能称逐字原始响应。
- ADR 区分实际验证、冻结选型、待裁决；Embedding 未确认时不虚填、不宣称 D1 全部完成。
- 学习者能解释自设字段与框架默认字段、超时/限流的阻塞点、token 用量。这一项必须由学习者回答，AI 运行不替代理解验收。
