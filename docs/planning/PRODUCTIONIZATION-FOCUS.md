# 资金网关智能守护 Agent：生产化增强聚焦计划

> 本计划服务于 Java AI 应用工程能力展示，不把学习型合成项目包装成真实生产系统。

## 目标

围绕一条可复现闭环增强工程可信度：

```text
指标异常 → Java 窗口与规则 → Agent 调查 → RAG 证据
→ 结构化报告 → Java 门禁 → 人工审批 → 模拟治理 → 审计反馈
```

最终要能回答三个问题：模型为什么得出这个结论、系统如何阻止错误动作、结果如何被评测和追溯。

## P0：本轮只做

1. **模型调用治理**：集中模型标识、Prompt 版本和调用审计；补齐可分类失败、有限重试、失败停止和结构化输出校验。
2. **Agent 边界治理**：限制工具白名单、调用步数、参数范围和无证据继续推理；明确模型结论、Java 规则、人工审批和模拟执行的责任边界。
3. **诊断评测契约**：基于固定合成集比较规则与 Agent，至少记录主因命中、证据支撑、缺证停止、工具选择、门禁结果、延迟和 Token。

## P1：P0 验收后再做

- 最小权限模型：用户、角色、资方范围、知识范围、工具权限和审批权限；先做服务层校验，不接真实身份系统。
- Redpanda 消费幂等、非法消息记录、失败重放和诊断任务恢复。
- 人工反馈与 Bad Case 回流，并将反馈关联到诊断任务和评测运行。

## 暂不做

MCP、语义缓存、第二模型、Rerank、多 Agent、真实生产监控、真实写操作、生产容量承诺、微服务拆分和模型训练均不进入本轮。

## 统一真实性边界

- 场景、指标、文档和故障样本均为合成验证材料。
- 治理动作只写入模拟记录，不连接真实生产系统。
- 评测结果只代表当前固定数据集和本地运行配置，不能外推为生产 SLA 或线上效果。

## 批次验收规则

每个批次必须同时提供：变更文件、对应单元/集成测试、失败路径证据、可复现命令和未完成事项。未通过测试或没有证据的能力，不进入简历表述。
