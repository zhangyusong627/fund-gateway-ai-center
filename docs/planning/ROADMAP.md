# FG-ADC 项目执行路线图

本文件是截至 2026-09-30 的唯一里程碑与依赖顺序。每日安排必须服从这里的前后依赖；HANDOFF 只记录当前状态和下一步。

## 当前状态

M0 D1-D5 与 M1-D1 已完成。当前正在完成 M1 最后一轮需求、范围和架构收敛。终审后先建设完整知识底座，再实现依赖它的资方接入和智能守护闭环。

## M0：机制实验（已完成）

完成多模块工程、DeepSeek 调用、结构化输出、Tool Calling、本地 BGE 512 维 Embedding 和 pgvector Top-K 单点验证。

## M1：需求与受控 Agent 基线（截至 9/11）

完成 M1-D1 三个只读工具、Java 规则、真实 Tool Calling、结构化报告、证据/权限/中文门禁和学习验收；冻结 PRD、SCOPE、业务架构、技术架构和依赖顺序。

**完成标准**：需求可用业务语言讲清楚；核心交付与未来扩展分开；设计不存在未实现即依赖的能力。

## M2：知识底座与 RAG 闭环（9/12–9/16）

完成文档版本、正文/表格解析、切分、BGE Embedding、pgvector 离线索引、在线检索、来源引用、固定问题集和基线/改进策略评测。

**完成标准**：一份文档可索引；问题可返回正确原文位置；检索指标可复算；失败查询有原因。

## M3：资方接入助手最小闭环（9/17–9/19）

只针对“用信申请”完成候选接口规范抽取、Java 结构/业务/来源校验、人工确认、不可变 V1 和发布事件。核心验收通过后，可选生成确定性 DTO 与校验骨架。

**完成标准**：条件必填和来源引用保留；缺引用无法发布；候选与发布版本隔离；全过程可回放。

## M4：智能守护实时指标链路（9/20–9/23）

接入 Redpanda，完成 Mock 指标生产、消费、10 秒/1 分钟窗口、核心特征、两个单指标场景、一个多指标场景、风险指纹、PostgreSQL 幂等、冷却和诊断任务。

**完成标准**：正常指标不触发；风险稳定复现；重复风险被抑制；指标消息数显著大于诊断任务数。

## M5：Agent 与 RAG 联合诊断（9/24–9/26）

诊断快照整合运行指标、规则结果、已发布接口规范和 RAG 引用；Agent 通过白名单只读工具补充调查，输出固定 JSON；Java 完成最终门禁、人工审核和模拟治理记录。

**完成标准**：模型调用远少于指标消息；结论有证据；缺证停止；硬冲突转人工；候选规范不可被读取。

## M6：双应用、故障与 Docker 交付（9/27–9/29）

使 fund-integration 与 fund-guardian 独立启动；完成数据库、Redpanda、模型和 RAG 故障验证；编写 Compose、初始化脚本、健康检查和端到端回放。

**完成标准**：两套应用可独立健康检查；依赖故障结果明确；一条 Compose 命令可启动必要服务并运行两条演示链路。

## M7：最终验收与面试材料（9/30）

运行全量构建、测试、RAG 评测、诊断评测和联合演示；整理架构、时序图、原始证据、已知限制、Java AI 知识点与项目讲述。

**完成标准**：干净环境可复现；所有结论有证据；学习者能独立讲解关键链路、边界和取舍。

## 核心依赖顺序

```text
需求冻结
→ 文档与 RAG
→ 候选接口规范 V1
→ 指标实时链路
→ Agent 联合诊断
→ 双应用与 Docker
→ 最终评测和讲解
```

RAG 必须先于依赖知识证据的两个业务闭环；实时指标必须先完成聚合和降频，才允许接入模型；核心验收未完成前不得启动代码生成扩展。

## 截止日边界

- 必需基础设施：PostgreSQL 16 + pgvector、Redpanda、Docker Compose。
- 不引入 Redis；除非后续有实测瓶颈并另立 ADR。
- 使用 Mock 监控和合成指标，不外推本机容量为生产指标。
- 每个里程碑必须完成实现、验证、代码讲解和三层学习验收。
