# FG-ADC 执行路线图

本文件是截至 2026-09-30 的唯一执行顺序。当前主线为“资方知识库 → 智能守护”；fund-integration 的 SPI 接入助手保持现状。

## 里程碑

| 阶段 | 目标 | 主要产物 | 完成标准 |
|---|---|---|---|
| M0-M4 | 已有基础能力 | 工程、RAG、指标、规则、Redpanda、pgvector | 既有证据和测试保持通过 |
| M5 | 知识库稳定化 | 文档版本、索引、检索、引用、评测和知识库 API | 固定问题集可复算，错误版本不混入 |
| M6 | 智能守护闭环 | 指标降频、快照、RAG/工具、模型、门禁、审核 | 正常/单指标/组合/缺证/冲突可回放 |
| M7 | 后台与交付 | 九页管理后台、Docker、联合回放 | 页面状态可追溯，Compose 可复现 |
| M8 | 最终验收 | 全量测试、学习讲解和交付材料 | 干净环境可复现，所有结论有证据 |

M8 增补记忆管理与受控 Agent 闭环：Prompt 版本、短期会话记忆、诊断工作记忆、摘要、有限多轮工具循环、长期已确认案例记忆和恢复验收。

## 依赖顺序

```text
知识文档解析 → 分片/Embedding → pgvector 索引 → 检索/评测
→ 诊断证据快照 → 指标窗口/规则降频 → Agent/门禁/审核
→ 九页后台 → Docker 联合回放 → 最终验收
```

知识库是智能守护诊断的证据前置；指标聚合和降频是模型调用前置；后台和 Docker 只在核心链路稳定后收口。

## 本期边界

- `fund-knowledge` 负责知识库能力；`fund-guardian` 负责智能守护；`fund-common` 仅共享通用对象。
- `fund-integration` 的既有 SPI/资方接入助手不删除、不扩展、不计入本期新增交付。
- `fund-experiments` 保留历史实验和回放，不进入最终业务拓扑。
- 只使用 PostgreSQL 16 + pgvector、Redpanda、DeepSeek、本地 BGE 和 Docker Compose；不引入 Redis、Flink、Kubernetes 或新的中间件。
- 数据使用合成指标和用户提供材料；不接真实监控、真实资方或生产写操作。
