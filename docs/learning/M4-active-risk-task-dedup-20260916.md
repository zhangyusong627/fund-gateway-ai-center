# M4 活跃风险任务归并改造记录

## 结论

同一种活跃风险不能把多个冷却放行窗口直接计为多个诊断任务。正确链路是：

```text
指标消息 → 时间窗口 → 风险规则 → 冷却 → 风险指纹
→ 查询活跃任务 → 已有则归并 → 没有则原子创建一个任务
→ 该任务独立执行 Agent / 模型
```

## 本次改造

- `riskWindows` 表示命中风险规则的窗口数。
- `suppressedTasks` 表示被冷却抑制的窗口数。
- `diagnosticTasks` 表示真实工作流任务数，不再表示冷却放行窗口数。
- 同一活跃风险通过工作流仓储查询和 PostgreSQL 部分唯一索引保持唯一。
- 任务进入拒绝、退回、过期或模拟完成等终态后，允许同一风险重新开案。

## 当前验证边界

定向自动化测试已通过；模型真实调用和数据库已有历史任务清理尚未在本次改造中执行。学习者仍需独立通过控制台模拟和数据库查询完成最终验收。
