# M0 D2 结构化输出验证记录

## 验证目标

基于升恒消费金融接口文档的“授信申请”字段定义，验证模型输出进入 Java 系统后，能够依次经过结构化映射、结构校验和业务校验。测试数据全部为合成数据，不代表真实客户或真实交易。

## 来源与范围

- 来源文档：升恒消费金融接口文档，授信申请请求参数章节。
- 本次范围：授信申请字段映射、文档声明的必填字段、日期格式、金额、利率和性别枚举。
- 本次不做：加解密、真实资方调用、SFTP 前置条件、工具循环、向量检索和代码生成。

## 三个核心样例

| 样例 | 处理阶段 | 预期结果 |
|---|---|---|
| 合法完整样例 | 映射 → 结构校验 → 业务校验 | 全部通过 |
| 缺少 `applyAmt` | 映射 → 结构校验 | 映射成功，结构校验失败 |
| 字段齐全但金额为负、利率超范围、证件日期倒置 | 映射 → 结构校验 → 业务校验 | 结构校验通过，业务校验失败 |

另有一个非法 JSON 测试，用于证明映射失败不会进入后续校验。

## 阶段结论

- 已运行：Java 映射、结构校验和业务校验测试全部通过。
- 已理解：JSON 可解析只证明映射成功，不能证明字段齐全或业务值有效。
- 待独立验证：下一轮由学习者脱离代码说明三个样例分别在哪一层通过或失败。

## 单次真实模型联调

- 触发方式：激活 `d2` profile，读取环境变量 `DEEPSEEK_API_KEY` 和临时注入的 `D2_PROMPT`，调用一次 `deepseek-v4-flash`。
- 提示词处理：完整提示词不写入代码、日志或证据，仅保存 SHA-256 指纹。
- 模型结果：返回内容可以映射，结构校验和业务规则校验均通过，但模型生成了疑似真实身份信息。
- 处理结论：Java 侧新增合成数据门禁，模型候选被拒绝；原始响应已脱敏，见 `docs/learning/D2-real-call-1788775359280/`。
- 这次联调的结论是“模型输出不能只看 JSON 和业务字段是否通过”，还必须执行数据来源与合成边界检查。
