## 两个发现与处理

1. **UI 缺按钮（已修复）**：控制台原先只有"批准/拒绝/退回"三个按钮，`/{taskId}/simulations`（治理模拟）与 `/{taskId}/memories`（案例沉淀）只能通过接口调用，且顺序反了会因状态已变 `SIMULATED` 被拒绝。已按正确顺序补上两个按钮，实现见下节。
2. **过期任务占用指纹（已修复）**：任务超过审批截止时间后仍是 `PENDING_APPROVAL`，被风险指纹去重视为活动任务，导致同场景再次模拟返回 `ACTIVE_TASK_EXISTS`。按用户裁定改为**自动置 `EXPIRED`**，实现见下节。

## 审批后两个动作的 UI 补齐与验证

- 视图层：`DiagnosticTaskView` 增加 `reviewOperationId`，让页面可以直接把审批操作号作为案例审批标识，形成可追溯的审批—案例关联。
- 页面层：审批通过后不再只显示完成提示，而是渲染"审批后动作"面板——先"沉淀长期案例"，再"执行治理模拟"，并展示治理动作、模拟参数和操作人输入；两个动作的结果就地回显。
- 运行验证（Codex 内置浏览器操作控制台 UI，非接口直调）：
  - 任务 `52f85dfd`：UI 批准 → 面板显示 `APPROVED` → 点"沉淀长期案例" → 回显"已沉淀长期案例：ACTIVE / NYXJ · credit-apply · 证据引用 10 条" → 点"执行治理模拟" → 回显"治理模拟已完成：SIMULATED / THROTTLE_QPS · SIMULATED_SUCCESS · 仅写入审计记录"。
  - 数据库核对：任务状态 `SIMULATED`；`confirmed_incident_memories` 2 条；`governance_simulations` 3 条。

## 过期任务自动置 EXPIRED 的实现与验证

- 领域层：`DiagnosticTask.expireIfOverdue(Instant)` 抽出原审批超时分支，返回是否发生状态变化并追加 `APPROVAL_EXPIRED` 事件；`review()` 复用它，行为不变。
- 应用层：`DiagnosticWorkflowService.expireOverdueTasks()` 扫描待审批任务并落库；`create()`、`findById()`、`findAll()` 三个入口先执行一次，过期任务不再占用风险指纹、也不再在页面上显示为待审批。
- 单元测试：新增"查询入口自动过期"与"同指纹过期后可创建新任务"两条，`fund-guardian` 71 项测试通过。
- 运行验证：新建任务 `ab5153d6`（`PENDING_APPROVAL`）→ 仅把 `review_deadline` 改为过去时间 → 只调用一次列表接口（未执行任何审批动作）→ 状态即为 `EXPIRED`，时间线最后一条为 `APPROVAL_EXPIRED / 审批已超过截止时间`。
- 说明：运行验证中为模拟时间流逝，直接改写了该合成任务的 `review_deadline`；这是验收库内的一次性测试数据操作，不影响其他记录。
