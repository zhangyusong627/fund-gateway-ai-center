# M8 学习者独立验收清单（2026-09-21）

> 用途：把 `docs/HANDOFF.md` 第 3 节的"下一步唯一动作"拆成可照做的四步。
> 前提：控制台运行在 `http://127.0.0.1:18080`，`/api/console/status` 的 `environment` 必须是 `acceptance`。
> 判定原则：机器记录 + 你能口述，两者齐全才算通过；AI 代跑只算"已运行"，不算"已独立验证"。

## 步骤 1 · 智能守护模拟（补齐消息降频）

页面：控制台"智能守护"。

填写：

| 字段 | 取值 |
|---|---|
| 指标场景 | `COMBINED`（错误 + 超时 + 线程池组合风险） |
| 指标消息数量 | `10000` |
| 同时真实调用一次 DeepSeek | 勾选 |
| 资方 | `NYXJ` |

期望结果：返回窗口聚合数、风险事件数、诊断任务数、冷却抑制次数，并生成 1 个新诊断任务，状态为 `PENDING_APPROVAL`。

核对：

```bash
docker exec fund-gateway-ai-center-postgres-1 psql -U fund_demo -d fund_acceptance -P pager=off -c \
"select status, count(*) from guardian.diagnosis_workflow_tasks group by 1;" \
-c "select count(*) as risk_events, max(created_at) from guardian.risk_events;" \
-c "select called_at, stage, status, input_tokens, output_tokens from guardian.model_call_audits order by called_at desc limit 2;"
```

通过标准：出现今天的新任务；风险事件数少于消息数（降频生效）；模型调用审计里新增一行 `guardian/diagnosis`。

需要能讲清：为什么 10000 条消息只产生少量诊断任务（窗口聚合 + 风险指纹 + 冷却）；模型拿到的是快照还是原始指标。

## 步骤 2 · 人工审批到模拟治理（当前完全缺失的一环）

在"诊断任务"里对步骤 1 产生的任务执行审批，或直接调用接口：

```bash
curl -s -X POST http://127.0.0.1:18080/api/console/guardian/diagnostics/<taskId>/reviews \
  -H 'Content-Type: application/json' \
  -d '{"action":"APPROVE","operationId":"m8-acceptance-<唯一串>","reviewer":"yusong","comment":"M8 独立验收"}'
```

核对：

```bash
docker exec fund-gateway-ai-center-postgres-1 psql -U fund_demo -d fund_acceptance -P pager=off -c \
"select status, count(*) from guardian.diagnosis_workflow_tasks group by 1;" \
-c "select count(*) as approvals from guardian.diagnosis_approvals;" \
-c "select count(*) as simulations, max(simulated_at) from guardian.governance_simulations;" \
-c "select count(*) as case_memories from guardian.confirmed_incident_memories;"
```

通过标准：审批记录 +1；`governance_simulations` 从 0 变为 1（治理只做模拟执行）；审批通过后生成一条长期案例记忆。

需要能讲清：为什么写操作必须停在 `PENDING_APPROVAL`；模型是否有权直接改参数；`operationId` 的作用（重复审批幂等）。

## 步骤 3 · 受控 Agent 模拟与记忆（验收库里从未跑过）

该能力目前只有 API，页面没有按钮：

```bash
curl -s -X POST http://127.0.0.1:18080/api/console/guardian/agent/replay \
  -H 'Content-Type: application/json' \
  -d '{"conversationId":"m8-acceptance-20260921","diagnosticTaskId":"<步骤1的taskId>","prompt":"请判断当前指标是否存在超时风险，并给出依据"}'
```

核对：

```bash
docker exec fund-gateway-ai-center-postgres-1 psql -U fund_demo -d fund_acceptance -P pager=off -c \
"select status, turn_count, tool_call_count, updated_at from guardian.agent_execution_states order by updated_at desc limit 3;" \
-c "select role, message_type, count(*) from guardian.conversation_memory_messages group by 1,2;" \
-c "select count(*) from guardian.conversation_memory_summaries;"
```

通过标准：执行状态为 `COMPLETED`、`turn=2`、工具调用 1 次；会话消息按 `conversationId + diagnosticTaskId` 落库；同一会话跨任务读取应被拒绝。

需要能讲清：Prompt 与上下文由哪几部分组装；短期记忆、诊断工作记忆、长期案例记忆的区别；哪一步是 Java 门禁而不是模型判断。

## 步骤 4 · RAG 补一条"限定版本 + 真实分数 + ACCEPTED"

页面："检索实验室"。

| 字段 | 取值 |
|---|---|
| 集合 | `fund-gateway-contracts` |
| 文档范围 | `nyxj-api@v1` |
| 关键词 | `授信申请`（必填，留空会 400） |
| 问题 | 不要出现"接口"二字，例如"授信申请的请求方式是什么？" |

通过标准：`ACCEPTED`，候选分数有区分度，并满足 `finalScore = 0.7 × 向量分 + 0.3 × 关键词命中率`。

如果问题里出现"接口"，会触发关键词精确补召回，分数被统一写成 1.0，不能用来讲召回分数。
