# ADR-012：管理后台采用 PostgreSQL 持久化并以已发布集合提供检索

- 日期：2026-09-12
- 状态：已接受

## 决策

1. `fund-console` 正式运行模式使用 PostgreSQL 保存文档版本、解析元素、分片、索引任务、诊断工作流、审批、模拟治理和模型调用审计；内存仓储只用于单元测试和明确的本地替身模式。
2. 知识库建表脚本由部署步骤显式执行，应用启动和在线检索不自动执行 DDL，也不写入演示分片。
3. 在线检索只能选择 `knowledge.rag_collections.status = 'PUBLISHED'` 的集合；索引完成前的 `STAGING` 集合不可见，失败索引不能进入检索。
4. 离线索引通过独立执行接口异步启动，页面轮询任务状态；模型、维度、归一化配置固定为本项目 ADR-009 的本地 BGE 512 维基线。
5. 智能守护工作流先保存风险事件，再保存诊断任务；模型调用保存完整原始请求、原始响应、状态、Token 和调用时价格快照，治理动作仍只做模拟。

## 影响

- 控制台重启后文档、索引状态、诊断审批和成本审计仍可恢复。
- 首次部署必须执行 `fund-knowledge/src/main/resources/knowledge-schema.sql` 和 `fund-guardian/src/main/resources/guardian-schema.sql`；脚本只创建本项目对象，不删除数据。
- 没有已发布集合时，状态接口返回 `DEGRADED`，检索明确返回“请先完成离线索引”，不能伪造成功。
