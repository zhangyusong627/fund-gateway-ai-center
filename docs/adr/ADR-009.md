# ADR-009：冻结 D4 实际 Embedding 与向量检索基线

- 日期：2026-09-10
- 状态：已接受
- 替代范围：替代 ADR-000 中“Embedding 待裁决、建议云 API”的未决部分；ADR-000 其余版本继续有效。

## 背景

D4 已经使用 Java 进程内本地模型完成真实向量生成，并写入 PostgreSQL + pgvector 完成在线 Top-K 检索。继续保留云 Embedding 候选作为权威基线会导致文档、索引维度和实际代码不一致。

## 决策

| 项目 | 冻结值 |
|---|---|
| 模型 | `BAAI/bge-small-zh-v1.5` |
| 运行方式 | Java 进程内本地 ONNX 推理 |
| 模型框架 | DJL `0.34.0` + ONNX Runtime `1.20.0` |
| 向量维度 | `512` |
| Pooling | attention mask 加权 mean pooling |
| 归一化 | L2 归一化 |
| 向量存储 | PostgreSQL 16 + pgvector |
| 模型文件 | 本地运行资源，不提交 Git |

文档向量与查询向量必须使用同一模型、同一 tokenizer、同一 pooling、同一归一化和同一维度。任何一项变化都必须建立新索引版本并全量重建向量，禁止在同一索引中混用。

## 影响

- 阿里云 `text-embedding-v4` 不再是当前实现基线，只保留为未来模型服务化候选。
- `fund-knowledge` 继续维护本地 Embedding 与 pgvector 适配能力。
- 本地模型增加进程内内存和原生运行时复杂度；若后续改为独立模型服务，必须另立 ADR、重新评测并重建索引。
