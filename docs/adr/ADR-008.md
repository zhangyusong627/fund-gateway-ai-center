# ADR-008：双业务域运行边界与基础设施收敛

- 日期：2026-09-10
- 状态：已接受；Redis、方法体生成与实现顺序已由 ADR-010 收缩
- 替代范围：替代 ADR-007 中“仅由正式告警触发”和“M1-D2 不接入消息中间件”的阶段性结论；不改变 ADR-007 关于 Java 规则、模型职责和人工审核的基本方向。

## 背景

FG-ADC 同时包含智能守护和资方接入助手。两者用户、触发频率、数据、资源消耗、权限和故障边界不同，不能继续作为一个 Spring Boot 进程中的同一业务链路。项目还需要在 2026-09-30 前完成真实 MQ、本地数据库、RAG、两条独立演示链路和 Docker Compose 验收，因此必须控制基础设施数量和设计模式范围。

## 决策

### 1. 产品与运行边界

- 保持一个 Git 仓库和统一 Maven 父工程。
- `fund-guardian` 是智能守护业务域，最终形成可独立启动的 Spring Boot 应用。
- `fund-integration` 是资方接入助手业务域，最终形成可独立启动的 Spring Boot 应用。
- `fund-knowledge` 保持共享 Java 能力模块，不在本期拆成独立微服务。
- `fund-common` 只保存通用标识、错误类型和审计关联信息，不保存任何业务域实体。
- `fund-application` 仅作为 M0/M1 实验入口过渡存在，不再承担最终统一运行装配；后续去留单独处理。

### 2. 业务域连接

资方接入助手拥有候选接口规范和已发布接口规范。人工确认后发布不可变版本，并产生 `ContractPublished` 事件。智能守护只消费已发布版本的只读投影，禁止读取候选版本或直接修改接入助手数据。

### 3. 消息与实时计算

- 本地 Docker 使用 Redpanda，业务代码面向 Kafka 协议。
- 第一版只保留 `guardian.metric-events.v1` 和 `integration.contract-published.v1` 两个必要 Topic。
- 指标消息进入 Java 有界窗口后计算 QPS、CPM、延迟百分位、错误率、超时率、线程池和 JVM GC 特征。
- 原始指标由 Redpanda 有限期保留；PostgreSQL 默认保存聚合窗口、异常样本、风险事件和诊断快照，不永久复制全部原始遥测。
- 不在本期引入 Kafka Streams、Flink 或通用流计算平台。

### 4. 数据与缓存

- 本地只部署一个 PostgreSQL 16 + pgvector 实例。
- 使用 `guardian`、`integration`、`knowledge` 三个逻辑 Schema 隔离数据所有权。
- 审计记录不设独立 Schema：智能守护审计归 `guardian`，资方接入审计归 `integration`，文档索引审计归 `knowledge`；三者通过 `traceId` 关联。
- Redis 只保存热点缓存、去重、冷却和频控状态，不作为事实数据库。
- 关键任务、审核、版本和执行结果以 PostgreSQL 为准；Redis 不可用时系统允许降级，但不得改变事实正确性。

### 5. 触发与冲突

- 智能守护同时支持趋势预防触发、正式告警触发和人工触发。
- 高频指标必须先经过窗口聚合、规则判断、风险指纹和冷却，再决定是否调用模型。
- 根因候选排序不同不视为硬冲突。
- 模型否认确定性规则、引用无效事实、提出越权动作或违反已发布接口规范时，才判定为硬冲突并进入人工审核。

### 6. 工程方法

- 两个业务域内部采用轻量 DDD 与六边形依赖：接口适配器调用应用用例，应用层编排领域对象，基础设施实现出站端口。
- 使用适配器、策略、责任链、仓储、状态转换和必要领域事件解决具体问题。
- 本期不引入微服务平台、Event Sourcing、Saga、CQRS 框架、状态机框架或通用规则引擎。

## 影响

- PRD、业务架构、技术架构、路线图和模块职责必须按双业务域重写。
- 现有 `fund-application` 中实验类在正式功能实现前保持不动；代码迁移另开任务并完整构建验证。
- PostgreSQL Schema 创建、数据迁移和模块删除仍需用户单独授权。
