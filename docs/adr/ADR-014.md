# ADR-014：资方接口文档内容可真实，机构名称必须合成

- 日期：2026-09-12
- 状态：已接受
- 决策人：用户（雨松）
- 执行：WorkBuddy

## 背景

ADR-001 第 2 条确立了「不写真实公司/机构名」的合规红线，但未明确这条红线是否同时约束资方接口文档的「内容」（字段定义、错误码、QPS 上限、超时约定、幂等规则等）。M2~M7 实施过程中使用了用户提供的真实资方接口文档作为解析与评测样本。本 ADR 把这条边界划清，避免后续把「文档内容真实」误判为违规、把「机构名称」误判为可写真实名。

## 决策

1. **资方接口文档的「内容」可以来源于真实金融机构的公开接口规范**。具体可使用：
   - 字段定义（名称、数据类型、是否必填、字段条件、说明）
   - 错误码与返回码定义
   - QPS / 超时 / 限流上限等数字约束
   - 幂等、重试、对账规则
   - 章节结构、表格样式、参数示例
   - 其他公开接口规范中的技术事实
2. **所有「机构名称」必须是合成名**，不得在任何位置出现真实持牌金融机构的名称、商号、品牌或拼音简写。对应「合成资方白名单」由 ADR-001 规则 3 与 ADR-013 共同确定（恒誉 / 云腾 / 衡丰 / 升恒 / 鼎瑞），后续命名变更须先写 ADR 再落地。
3. **代码、文档、HANDOFF、ADR、commit 信息、求职材料、简历、控制台页面、运行时接口响应**等所有面向人/机器阅读的位置，机构名都必须用合成名。
4. **documentId / chunkId / collection_id / endpoint 路径**等机器标识符必须以合成资方名作为前缀或主体（如 `shengheng-consumer:v1:117`、`dingrui-bank-api`）；不得用真实机构拼音或缩写。
5. **本地 docx 文件命名**遵循同一规则：文件名用合成资方名（如 `升恒消费金融接口文档.docx`），文件内容可以保留真实接口规范字段。
6. **git 历史与 commit 信息**：合规检查不仅看当前工作区，也要看 commit 历史；commit 信息里不得包含真实机构名作为违规描述（仅可作为「迁移记录」提及旧名时要慎重，且必须配合文档化的迁移说明）。

## 影响

- ADR-013 第 1 条「升恒替换原 [OLD_NAME_A]、鼎瑞替换原 [OLD_NAME_B]」的命名映射仍然成立，但「文档内容」一栏不再需要替换——M2 解析用的 docx 内容字段保持真实接口规范即可，仅文件名和 documentId 标识符换成合成名。
- 测试用例与 M2 固定评测集的「字段内容」保持真实接口规范字段不变；只把「机构名引用」换成合成名。
- 后续如有新资方接入，按 ADR-013 + ADR-014 双轨：先选合成名（必要时扩白名单写 ADR），再用真实接口文档内容做样本。

## 验证

- `grep` 仓库内（排除 `target/`、`.git/`、`.workbuddy/`、`.idea/`）搜真实机构禁词集（具体搜索串在执行时填入，不在本 ADR 文本中固定列出，避免 ADR 自身命中）应返回空。
- ADR-013 第 4 条的本地 docx 重命名仍由用户在终端手工执行；重命名后 docx 文件内容字段保持真实接口规范不变。
- `mvn -B verify` 通过，运行时控制台展示的 documentId / chunkId 全部以合成资方名前缀呈现。

## 与既有 ADR 的关系

- 不废除 ADR-001，仅补充 ADR-001 第 2 条「不写真实机构名」的边界范围（名称必须合成，内容可真实）。
- 不废除 ADR-013，但 ADR-013 第 1 条与第 4 条的语义在 ADR-014 生效后被重新解释：第 1 条的「升恒替换原 [OLD_NAME_A]」映射保留；第 4 条的「重命名」不再要求重写 docx 文件内容。
