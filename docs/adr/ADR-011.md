# ADR-011：核心范围收敛为资方知识库与智能守护

- 日期：2026-09-12
- 状态：已接受
- 取代范围：仅取代 ADR-010 中“本期保留资方接入助手核心闭环”及其对应实施排期；ADR-000～ADR-009 的技术基线、数据口径、边界和工具安全决策继续有效。

## 背景

当前工程同时包含知识底座、资方接入助手和智能守护。继续并行推进三个业务闭环，会把文档解析、RAG、实时指标、Agent、审核、SPI 规范抽取和代码生成混成一个交付目标，导致学习重点分散、验收标准不清晰。资方接入助手的已有代码和 M3 证据可以保留，但它不是当前截止日前的主交付。

## 决策

1. 截止 2026-09-30 的核心交付收敛为两个能力域：
   - **资方知识库**：文档登记、解析、切分、Embedding、pgvector 索引、检索、引用、评测和管理后台。
   - **智能守护**：合成指标接入、窗口特征、确定性风险规则、降频、诊断快照、RAG/只读工具、结构化中文报告、门禁、人工审核和模拟治理。
2. `fund-integration` 的资方接入助手（候选接口规范、人工发布、不可变 V1、发布事件）保持现状，作为历史已验证能力和后续扩展，不继续扩展 SPI、DTO 生成或真实资方接入。
3. 本期主链路是：`知识库 → 智能守护诊断`。运行指标、规则结果和审计记录进入结构化存储；文档和知识片段进入 RAG；模型只消费经过 Java 组装的证据并生成候选结论。
4. 管理后台按九个页面组织验收：运行总览、文档管理、索引任务、检索实验室、RAG 评测、智能守护运行总览、诊断任务、人工审批、模型成本与审计。文档解析作为文档详情，指标窗口和风险事件作为守护总览中的下钻视图。页面是业务入口和验收视图，后端 API 和领域服务仍按模块边界实现。
5. 必需基础设施仍为 PostgreSQL 16 + pgvector、Redpanda、DeepSeek、本地 BGE 和 Docker Compose；不引入 Redis、Flink、Kubernetes 或新的消息中间件。

## 影响

- PRD、SCOPE、ROADMAP 和架构说明以本 ADR 为当前范围基线。
- M3 的现有代码和学习证据不删除、不伪装成当前主线；后续只在核心交付完成且另行排期后恢复。
- 当前优先顺序改为：知识库可用 → 守护链路稳定 → 后台九页可验收 → Docker 联合回放 → 最终验收。
- “双应用”在本期解释为智能守护应用与知识库管理入口的可运行交付；资方接入助手应用保持现状，不作为新增交付目标。
