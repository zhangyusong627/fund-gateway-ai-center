# ADR-013：合成资方白名单扩展与历史真实机构名替换

- 日期：2026-09-12
- 状态：已接受
- 决策人：用户（雨松）
- 执行：WorkBuddy

## 背景

ADR-001 第 2 条把合成资方白名单固定为「恒誉 / 云腾 / 衡丰」。M2~M7 实施过程中使用了升恒消费金融、鼎瑞银行两家中国银保监会批准的持牌金融机构作为演示文档与评测样本，并在 M3 资方接入助手调用样例里保留了 `shengheng-credit`（前公司内部代号）与 `升恒` 字样。上述命名直接违反 ADR-001 规则 1（不得出现前公司内部系统代号）和规则 3（合成资方白名单）。本 ADR 对历史命名做一次性迁移并明确新白名单。

## 决策

1. **合成资方白名单扩展为五个**：恒誉 / 云腾 / 衡丰 / 升恒 / 鼎瑞。其中：
   - **升恒** 替换原「升恒消费金融」（消费金融公司），前缀 `shengheng`，docx 文档名 `升恒消费金融接口文档.docx`。
   - **鼎瑞** 替换原「鼎瑞银行」（民营银行），前缀 `dingrui`，docx 文档名 `鼎瑞银行接口规范.docx`。
2. **历史真实机构名一次性迁移**：升恒消费金融、升恒、shengheng-consumer、鼎瑞、鼎瑞银行、DINGRUI、DINGRUI-bank-api、shengheng、shengheng-credit、升恒在本仓库内全部替换为对应合成名。迁移对象包括 Java 代码、HTML 前端、文档、HANDOFF、AGENTS、ADR、JSON 数据、Maven 资源、SQL schema、单元测试 fixture。
3. **不动数据库旧记录**：Docker Compose 启动时若 pgvector 中已有按旧 document_id 写入的索引，需要重建索引或清库后重新登记，本次只改源代码与文档，不改运行时数据；M7 自验收前由学习者决定是否清库重建。
4. **本地文件目录同步**：`/Users/zhangyusong/Downloads/求职面试/金融机构标准接口文档/` 下的 `升恒消费金融接口文档.docx` 重命名为 `升恒消费金融接口文档.docx`；如有鼎瑞银行相关文件同步重命名为 `鼎瑞银行接口规范.docx`。本次 ADR 只约束仓库内的命名；本地文件目录的重命名由用户在终端手工执行。
5. **commit 提交但暂不 push**：替换完成后做一次 `git commit`，提交信息说明 ADR 编号与替换范围；远程推送由用户单独确认，避免在 M7 自验收前引入不可回滚变更。

## 影响

- 任何引用 `shengheng-consumer` / `DINGRUI` / `shengheng-credit` 作为 documentId、chunkId 前缀或 endpoint 路径的代码、JSON、文档需要同步替换；本 ADR 的替换是字面替换，不改变业务语义。
- ADR-001 规则 3 的白名单文本同步更新为「恒誉 / 云腾 / 衡丰 / 升恒 / 鼎瑞」。
- 测试用例与 M2 固定评测集的预期输出同步改名为合成资方名。
