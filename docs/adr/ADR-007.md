# ADR-007：M1 诊断以生产告警触发和多指标证据为输入

## 状态

已接受

## 决策

M1 的诊断流程由生产监控告警触发。系统先采集并形成同一诊断快照，再交给 Java 规则和模型分析。快照至少区分运行时指标、历史指标和已确认契约；运行时指标支持异步消息落库，也允许在时效性要求高时直接消费消息后计算并异步落库。

诊断同时支持单指标规则和多指标组合规则。指标范围可扩展到 QPS、CPM、P95、P99、HTTP/Tomcat 线程池、GC 次数/耗时/频率等。Java 规则负责确定性判断，模型负责基于原始指标、历史趋势和专业知识进行根因分析、风险排序、缺失证据识别和治理建议生成。

模型建议与专家规则冲突时，直接触发人工审核，不进入自动执行。当前项目的人工审核人是项目所有者本人。未来只有在垂直诊断模型经过独立评测并重新冻结决策后，才考虑调整优先级。

## 原因

仅把已有治理建议交给模型会退化为文本改写，无法体现模型在多证据关联和根因分析上的价值。告警触发和统一快照可以保证诊断及时且证据版本一致；规则与模型分离可以兼顾可控性和分析能力。

## 影响

M1-D2 的验收重点改为：告警触发、快照采集、多指标组合、规则与模型冲突识别，以及模型是否提供超出规则复述的分析价值。暂不实现真实生产监控接入、消息中间件或自动配置变更，继续使用合成适配器验证数据流和决策边界。
