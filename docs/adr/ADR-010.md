# ADR-010：核心交付范围与实现顺序收敛

- 日期：2026-09-10
- 状态：已接受
- 关联：补充 ADR-008 的双业务域结论；不改变 ADR-009 的 Embedding 基线。

## 背景

早期设计同时纳入实时计算、RAG、完整代码生成、隔离执行、Redis 和双应用交付，超过个人学习项目在 2026-09-30 前能够充分实现、验证、理解和讲述的合理范围。路线图还将依赖 RAG 的诊断安排在完整知识底座之前，存在依赖倒置。

## 决策

- 保留资方接入助手和智能守护两个业务域，因为它们分别承载 RAG 与 Agent 的核心学习目标。
- 核心业务闭环收敛为“文档到已发布接口规范”和“指标到受控诊断报告”。
- 先完成文档解析、离线索引、在线检索、引用和评测，再实现依赖知识证据的业务功能。
- 资方接入助手只对“用信申请”完成候选规范、Java 校验、人工确认和不可变 V1。
- 智能守护只实现核心指标、两个单指标场景和一个多指标场景，并在聚合、风险、去重和冷却后调用模型。
- Redis、模型方法体生成、通用代码生成和复杂隔离执行平台不进入本期核心范围。
- 核心闭环通过后，可增加一个确定性 DTO 与校验骨架生成演示，但不得影响截止日验收。
- 必需基础设施仅为 PostgreSQL 16 + pgvector、Redpanda、DeepSeek、本地 BGE 和 Docker Compose。

## 影响

- PRD、SCOPE、ROADMAP、业务架构和技术架构按上述边界同步。
- M2 调整为知识底座与 RAG，实时指标链路顺延到 M4。
- Redis 只有在出现可复现瓶颈且另立 ADR 后才能引入。
- ADR-008 中关于 Redis 和受限方法体生成的规划由本 ADR 收缩；其双业务域、Redpanda、三 Schema 和轻量 DDD 决策继续有效。
