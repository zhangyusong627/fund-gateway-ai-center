# 资金网关智能守护 Agent PRD

> 内部工程代号：FG-ADC 资金网关智能决策中心
>
> 项目副标题：面向资金网关异常诊断与受控治理的 Java AI 应用工程

- 文档状态：范围冻结基线
- 截止时间：2026-09-30
- 项目性质：Java + AI 个人工程化验证与作品集项目
- 数据边界：用户提供材料和运行数据均按合成数据使用，不连接真实生产系统

## 1. 产品目标

项目围绕“资金网关智能守护 Agent”交付一条可追溯、可验证的 Java AI 工程链路：

- **资方知识库**把接口文档、产品资料变成可检索证据，回答“原文在哪里、版本是什么”。
- **智能守护 Agent**把高频运行指标变成少量诊断任务，回答“哪里异常、依据是什么、建议是否可控”。

模型只提供概率性分析；Java 负责确定性计算、结构/证据/权限/规则门禁和流程状态。

## 2. 本期范围

### 2.1 资方知识库

文档登记、版本管理、正文和表格解析、语义分片、BGE Embedding、pgvector 离线索引、在线 Top-K 检索、来源引用、固定问题集评测和失败记录。

### 2.2 智能守护

合成指标事件、Redpanda 消费、10 秒/1 分钟窗口、QPS/CPM/P95/P99/错误率/超时率/线程池/GC 特征、单指标与组合规则、指纹/去重/冷却、PostgreSQL 任务、诊断快照、RAG 与白名单只读工具、DeepSeek 固定 JSON 报告、Java 最终门禁、人工审核和模拟治理记录。

### 2.3 暂缓能力

fund-integration 中已有 SPI/资方接入助手代码和证据保持现状，作为后续扩展参考。本期不新增候选规范、DTO 生成、真实资方接入或发布流程开发。

## 3. 用户与场景

| 用户 | 场景 | 结果 |
|---|---|---|
| 接入开发 | 搜索接口字段、错误码和条件 | 看到分片、版本和原文位置 |
| 运维/开发 | 指标趋势达到风险条件 | 获得少量可追溯诊断任务 |
| 审核人 | 报告缺证或与规则冲突 | 审核、拒绝或记录模拟治理 |
| 项目所有者 | 复盘一次诊断 | 按 traceId 查到输入、证据、模型、门禁和结果 |

## 4. 九页管理后台

1. **运行总览**：文档数、索引状态、指标吞吐、风险数、诊断任务数和门禁结果。
2. **文档管理**：文档、版本、哈希、来源、解析状态，以及正文、表格、分片和来源位置详情。
3. **索引任务**：Embedding 与 pgvector 索引任务、处理进度、模型、维度和失败原因。
4. **检索实验室**：查询参数、向量分、关键词分、融合分、证据门禁和原文引用。
5. **RAG 评测**：固定问题集、Recall@K、MRR、引用命中率、拒答率和失败样例。
6. **智能守护运行总览**：合成指标、窗口特征、数据质量、规则版本、风险指纹、冷却和任务关联。
7. **诊断任务**：快照、RAG 引用、工具轨迹、模型调用、门禁状态和处理时间线。
8. **人工审批**：待审批报告、模型与规则冲突、审核动作、意见和模拟治理入口。
9. **模型成本与审计**：原始请求/响应、Token、估算费用、延迟、工具调用和 traceId 审计。

页面只展示后端已确认的数据，不能绕过 Java 规则、版本和权限门禁。

## 5. 端到端流程

```text
文档登记 → 解析/分片 → BGE 向量化 → pgvector 索引 → 检索/引用/评测
                                                        ↓
合成指标 → Redpanda → 窗口特征 → Java 风险与降频 → 诊断快照
                                                        ↓
                              RAG + 只读工具 → DeepSeek JSON → Java 门禁
                                                        ↓
                                      报告展示 / 人工审核 / 模拟治理
```

运行指标与任务状态进入结构化存储；文档分片和来源进入知识库；模型不得自行补事实或执行写操作。

## 6. 功能需求

### FR-01 文档知识库

记录文档标识、版本、格式、哈希、来源和状态；解析正文/表格并保留位置；失败文档不得进入可检索状态。

### FR-02 索引与检索

文档和查询使用同一 BGE 模型、512 维和归一化配置。pgvector 返回 Top-K 分片、版本和来源位置；固定集结果可复算。

### FR-03 指标与风险

事件必须包含服务、接口、指标、值、单位、观测时间、来源和 traceId。窗口计算采用原始样本，风险包含规则版本、证据、指纹和数据质量。重复风险不得在冷却期重复创建任务。

### FR-04 诊断 Agent

Java 先固化快照，再允许模型访问白名单只读工具和 RAG。输出必须是固定 JSON，包含根因候选、证据引用、缺口、建议和审核标记。

诊断 Agent 以 `conversationId` 管理短期会话记忆，以 `diagnosticTaskId` 隔离诊断工作记忆。Agent 可以在固定轮次内请求只读工具并接收 Java 回灌结果；上下文超限时只允许摘要历史消息，不得压缩或替换当前诊断证据。人工审批通过的诊断才可形成带证据引用的长期案例记忆。

### FR-05 门禁与审核

Java 校验 JSON 结构、枚举、引用、规则一致性、权限和中文内容。无效引用/非法结构拒绝；硬冲突、缺证和越权建议转人工。治理动作只做模拟记录。

### FR-06 可追溯性

以 traceId 关联指标、任务、快照、文档版本、检索结果、模型请求/响应、工具轨迹、门禁和审核。认证信息不能进入记录。

## 7. 非功能要求

- 可复现：固定合成输入可重放，结果含版本和计算方式。
- 可观测：关键状态、延迟、失败原因和模型调用次数可查询。
- 可控：单条指标不直接调用模型；模型无写权限。
- 性能：报告本机实测吞吐和延迟，不外推生产容量；模型调用量显著低于指标消息量。
- 可靠：MQ、数据库、RAG、模型分别有安全失败路径；不能以空数据伪造成功。
- 工程：Java 21、Maven、Spring Boot/Spring AI 基线不变；无 Python。

## 8. 数据与模块边界

- fund-knowledge：文档、分片、Embedding、pgvector、检索和评测。
- fund-guardian：指标、风险、诊断、Agent、门禁、审核和模拟治理。
- fund-console：管理后台页面、入站 API、进度展示和跨模块只读聚合。
- fund-common：通用标识和审计关联信息。
- fund-integration：暂缓的既有 SPI/资方接入助手，保持现状。
- fund-experiments：历史实验与模拟入口，不属于最终业务边界。

## 9. 验收标准

1. 一份文档可完成登记、解析、索引、检索和引用评测。
2. 版本和来源可追溯，错误文档/错误版本不会混入检索。
3. 正常、单指标、组合指标和重复风险均可稳定模拟。
4. 诊断报告经结构、证据、规则、权限和中文门禁，缺证/冲突可转人工。
5. 九页后台能展示上述状态和失败原因，不提供越权操作。
6. Docker Compose 可启动 PostgreSQL/pgvector、Redpanda 和本期应用并完成一次合成模拟。
7. mvn -B verify 通过，关键链路有原始证据和学习记录。
