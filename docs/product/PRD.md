# FG-ADC 资金网关智能决策中心 PRD

- 文档状态：核心交付基线，待用户终审
- 截止时间：2026-09-30
- 项目性质：Java + AI 个人学习与作品集工程
- 数据边界：使用用户提供材料和合成运行数据，不接入真实生产系统

## 1. 产品定位

FG-ADC 面向资金网关中两个高成本问题：资方接口文档理解依赖人工、生产异常诊断依赖专家经验。项目用两个可独立演示的最小业务闭环证明 Java 与 AI 的融合应用能力：

1. **资方接入助手**：从资方文档建立可追溯知识索引，抽取“用信申请”接口的候选规范，经 Java 校验和人工确认后发布不可变版本。
2. **智能守护**：将高频合成指标聚合为少量风险事件，结合 Java 规则、运行证据、已发布接口规范和 RAG 知识，由受控 Agent 生成诊断报告。

两个业务域共享知识能力，只通过已发布接口规范连接。模型提供概率性分析，Java 负责确定性计算、校验、权限和流程控制，人工裁决硬冲突。

## 2. 用户价值与成功标准

| 问题 | 系统价值 | 可验证结果 |
|---|---|---|
| 文档长、表格多、条件必填复杂 | 降低定位接口事实和核对来源的成本 | 每项候选事实可反查原文位置 |
| 指标高频且相互关联 | 在调用模型前聚合、筛选和降频 | 指标消息数显著大于诊断任务数和模型调用数 |
| 模型输出不稳定 | 用结构、证据、规则、权限和语言门禁约束 | 非法输出被拒绝，硬冲突进入人工审核 |
| AI 工程容易停留在 Demo | 以测试、评测、证据和 Docker 复现闭环 | 两条链路可运行、可回放、可讲解 |

截止日成功必须同时满足：

- 一份资方文档完成解析、离线索引、在线检索、引用和检索评测。
- “用信申请”完成候选规范、Java 校验、人工确认和 V1 发布。
- 合成指标完成 Redpanda、窗口计算、单项/组合风险、去重冷却和诊断任务创建。
- Agent 使用只读工具与 RAG 输出结构化中文报告，并通过 Java 门禁或进入人工审核。
- Docker Compose 可复现 PostgreSQL/pgvector、Redpanda 和两套应用；每阶段有运行、理解和独立验证记录。

### 3.1 核心交付

- Java 21、Spring Boot、Spring AI、多模块 Maven 工程。
- 本地 BGE Embedding、PostgreSQL 16 + pgvector。
- 文档版本、解析、切分、离线索引、在线检索、来源引用和固定问题集评测。

- QPS、P95、P99、错误率、超时率、线程池水位和 GC 核心指标。
- 单指标规则、一个多指标规则、风险指纹、去重、冷却和诊断快照。
- DeepSeek Tool Calling、结构化输出、证据/规则/权限/中文门禁和人工审核。
- 模拟治理建议与结果记录，不执行真实写操作。
- 自动化测试、评测、原始证据、Docker Compose 和演示讲解材料。

### 3.2 有条件扩展

只有核心闭环全部通过后，才允许增加一个基于已发布规范的**确定性 DTO 与校验骨架生成**演示。它不使用模型自由生成文件，不影响核心验收。

### 3.3 本期不做

- 模型方法体生成、通用代码生成平台和复杂隔离执行平台。

- 真实 Prometheus、SkyWalking、资方系统、生产流量和生产配置写入。
- 自动修复、垂直模型训练、预测算法平台、多 Agent、Flink、Kubernetes、微服务治理和高可用集群。
- 对生产容量、真实准确率或自动治理效果作未经验证的承诺。

## 4. 角色与权限

| 角色 | 职责和边界 |
|---|---|
| 接入开发/审核人 | 登记文档、核对候选事实、批准或退回接口规范 |
| 运维/开发人员 | 查看风险、发起人工诊断、核验证据和报告 |
| Java 规则层 | 计算窗口和风险，执行确定性校验，不调用模型 |
| 诊断 Agent | 读取白名单工具和 RAG，生成候选根因及只读建议 |
| 项目所有者 | 裁决硬冲突，批准或拒绝模拟治理 |
| Mock 指标源 | 产生可重复的合成指标，不拥有业务权限 |

## 5. 端到端业务流程

### 5.1 知识底座

```text
登记文档版本 → 解析正文/表格 → 语义切分 → BGE Embedding
→ pgvector 建索引 → 查询向量化 → Top-K 检索 → 来源引用 → 固定集评测
```

离线索引必须先于所有依赖 RAG 的业务功能。文档向量和查询向量必须使用同一模型、维度及归一化配置。

### 5.2 资方接入助手

```text
选择“用信申请” → 检索相关文档证据 → DeepSeek 抽取候选事实
→ Java 结构/业务/来源校验 → 人工确认 → 发布接口规范 V1
```

候选事实不能被智能守护读取。发布版本不可修改，修正必须产生新版本。

### 5.3 智能守护

```text
Mock 指标 → Redpanda → 窗口与特征 → Java 风险规则
→ 指纹/去重/冷却 → 诊断快照 → RAG 与只读工具 → DeepSeek
→ 结构化报告 → Java 最终门禁 → 报告或人工审核 → 模拟治理记录
```

单条指标不得直接调用模型。正式告警可以触发事后诊断；趋势或组合规则可以在正式告警前触发预防性分析。

## 6. 功能需求

### FR-01 文档与索引

系统必须记录文档标识、版本、文件哈希、格式、来源和解析状态；解析正文与表格，生成可追溯分块。索引记录模型标识、512 维、归一化配置和索引版本。失败文档不得进入可检索状态。

### FR-02 在线检索与评测

查询实时生成向量，通过 pgvector 返回 Top-K 分块及文档、版本、页码或章节位置。使用固定问题集计算至少 Recall@K 和引用命中率，保存失败查询及原因。第一版只需比较一种基线策略和一种改进策略，改进策略可为关键词与向量的简单融合。

### FR-03 候选接口规范

系统只针对“用信申请”抽取接口地址、方法、字段、类型、必填、条件必填、枚举、错误码及来源引用；QPS、超时、签名和幂等仅在文档明确声明时抽取，不允许模型补猜。

### FR-04 Java 校验与人工发布

Java 校验固定 JSON 结构、字段关系、条件表达和来源是否存在。审核人可以批准、拒绝或退回。批准后发布不可变 V1，并产生 `integration.contract-published.v1`；智能守护只保存已发布版本的只读投影。

### FR-05 指标消息

Mock 生产者向 `guardian.metric-events.v1` 写入统一指标事件，至少包含资方、接口、指标名、值、单位、观测时间、来源和 traceId。业务代码使用 Kafka 协议，本地由 Redpanda 承载。

### FR-06 窗口与特征

消费者按资方和接口形成 10 秒及 1 分钟有界窗口，计算 QPS、P95、P99、错误率、超时率、线程池水位和 GC 特征，记录样本量、计算版本及 COMPLETE、PARTIAL、STALE、UNKNOWN 数据质量。百分位基于同一窗口原始样本计算，不对已有百分位求平均。

### FR-07 风险与降频

Java 至少实现两个单指标场景和一个多指标场景。风险结果包含等级、命中规则、证据和规则版本。系统按资方、接口、风险类型生成指纹，在 PostgreSQL 中保证诊断任务幂等，并用应用逻辑实现冷却；风险升级允许重新触发。

### FR-08 诊断快照

模型调用前固化指标窗口、规则结果、已发布接口规范、RAG 引用和工具可用范围。关键证据缺失时停止确定性结论，不得让模型自行补齐事实。

### FR-09 Agent 与工具

模型可以调用白名单只读工具查询运行快照、历史基线和已发布接口规范。Java 的 `ToolCallingManager` 负责识别请求、校验参数、执行工具、回灌结果和限制循环步数。模型不能直接执行工具或写操作。

### FR-10 结构化报告与门禁

报告固定为 JSON，包含摘要、根因候选、证据引用、证据缺口、治理建议、规则对照和人工审核标记。Java 校验结构、枚举、引用、规则、权限和用户可见中文。无效引用和非法结构直接拒绝；否认确定性规则、越权动作或违反已发布规范时进入人工审核。

### FR-11 审核、模拟治理与审计

本期审核人为项目所有者，支持通过、拒绝和冲突。通过后只记录模拟治理结果。保存 traceId、模型/提示词/规则/接口规范/知识版本、请求响应、工具轨迹、门禁和审核结果；认证信息不得写入证据。

### FR-12 降级

模型不可用时保留 Java 风险结果；RAG 无结果时标记证据不足；Redpanda 消费失败有限重试并留下失败记录；PostgreSQL 不可用时停止创建新诊断任务。降级不得伪造完整报告。

## 7. 数据与模块边界

- `knowledge` Schema：文档、版本、分块、向量、来源、索引和检索评测。
- `integration` Schema：接入任务、候选规范、审核和已发布接口规范。
- `guardian` Schema：窗口、风险、诊断快照、报告、审核和模拟治理。
- 审计记录写入所属 Schema，以 traceId 跨域关联。
- `fund-knowledge` 提供共享 RAG 能力；`fund-integration` 和 `fund-guardian` 最终独立启动；`fund-common` 不放领域实体。
- 原始指标由 Redpanda 有限期保留，PostgreSQL 不永久复制全部原始遥测。

## 8. 非功能与验收指标

| 维度 | 本地验收口径 |
|---|---|
| 可复现 | 一条 Compose 命令启动必要服务，两条业务链路使用固定合成输入可重放 |
| 可控 | 模型无写权限；非法输出、无效证据和硬冲突均有确定结果 |
| 可追溯 | 任一报告可反查模型、提示词、规则、规范、知识版本和来源 |
| 性能 | 以本机实测报告吞吐和延迟，不外推生产容量 |
| 成本 | 模型调用次数必须小于诊断任务数加人工调用数，且远小于指标消息数 |
| 质量 | RAG 有固定集指标；诊断有正常、单指标、多指标、缺证和冲突案例 |
| 工程 | `mvn -B verify` 通过，两套应用独立健康检查，失败路径有测试 |

## 9. 最终验收场景

1. 文档完成索引，问题能返回正确来源；错误版本不能混入结果。
2. “用信申请”候选规范包含条件必填和来源，缺失引用时无法发布。
3. 正常指标不创建诊断任务；单指标和多指标风险按预期触发。
4. 重复风险在冷却期内不重复调用模型，风险升级可以再次触发。
5. Agent 使用工具与 RAG 后生成结构化中文报告。
6. 虚构证据、未知规则、越权建议和硬冲突被正确拦截或转人工。
7. 模型、RAG、MQ、数据库故障分别产生明确的安全失败结果。
8. 已发布接口规范可成为诊断证据，候选规范不可见。
9. Docker Compose 启动后，两套应用可分别演示并完成一次联合回放。
