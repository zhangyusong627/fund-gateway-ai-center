# 范围与验收

## 做什么

FG-ADC 是 Java + AI 个人学习与作品集工程，保留两个可独立演示的最小业务闭环：

- 资方接入助手完成“文档 → RAG → 用信申请候选规范 → Java 校验 → 人工确认 → 不可变 V1”。
- 智能守护完成“合成指标 → Redpanda → 窗口与风险 → 受控 Agent → Java 门禁 → 人工审核 → 模拟治理”。

本期共享本地 BGE Embedding、PostgreSQL + pgvector 和可追溯证据；最终通过 Docker Compose 复现。代码生成只允许在核心验收完成后增加一个确定性 DTO/校验骨架演示，不属于核心验收。

## 不做什么

不做模型方法体生成、通用代码生成、复杂隔离执行平台、Redis、真实监控或资方接入、生产写操作、自动修复、模型训练、预测平台、多 Agent、Flink、Kubernetes、微服务平台或生产级高可用。

## 验收是什么

- `mvn -B verify` 通过，两套应用独立启动并健康检查。
- 文档离线索引、在线检索、引用和固定集评测完整可回放。
- “用信申请”候选规范必须有来源，未经 Java 校验和人工确认不能发布。
- 高频指标经窗口、规则、去重和冷却后只产生少量诊断任务。
- Agent 只使用白名单只读工具和 RAG；结构、证据、规则、权限、中文门禁有效。
- 已发布接口规范可成为诊断证据，候选版本不可见。
- Docker Compose 启动 PostgreSQL/pgvector、Redpanda 和两套应用并完成合成验收。
- 每阶段分别记录已运行、已理解和已独立验证。
